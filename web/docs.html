How it works

blog.dliu.com is a blog that anyone can read and only the owner (or an agent with the owner’s Microsoft access token) can write. There are no servers: published posts are plain files in S3, CloudFront delivers them, and one small Lambda function runs only when the owner signs in, saves a post or uploads a file.

Running costs

Everything is billed per use. With nobody writing, the only charge is storing the pictures and files in S3; reading the blog runs no code.

Security

Anyone can read published posts; only the owner, signed in with Microsoft, can write, publish or delete, and can let an AI agent write through the Microsoft API with a short-lived Microsoft access token. Draft text never leaves the database.

The writing API

Machine-readable version: /docs/api.md

The owner can let a trusted AI agent or script write posts for them. It uses a separate Microsoft API, with a short-lived access token the owner gets by signing in with Microsoft. Readers never use this API.

What this API doesn’t do

  • No reactions, comments, sign-in or website pages.
  • It doesn’t issue, renew or store tokens: they come only from auth.dliu.com.
  • The website’s own /api/ knows only website sign-in and doesn’t accept these tokens.
  • Agents are told to save drafts unless asked to publish; deleting can’t be undone.

How the blog is checked

Machine-readable version: /docs/health.md

Every 15 minutes, status.dliu.com checks this blog the way an ordinary visitor would: it never signs in and never changes anything. It opens the public pages and links, then asks the blog to check its own database, storage and sign-in settings.

What isn’t tested

A guest can’t check anything that needs the owner to sign in or that changes content:

  • Signing in itself, and writing, editing, publishing and deleting once signed in.
  • Uploading or deleting pictures and files.
  • The Microsoft API for AI agents (it needs a Microsoft access token).
  • Leaving a reaction (that is a write).
